# ראיות מאזן החניה

המקור שממנו נבנה `data/parking.json`. **לא נגזר מחדש בלחיצת כפתור** — מאחורי הקבצים
האלה עומדת קריאה ויזואלית של מאות טבלאות מאזן חניה בנספחי תנועה, ולכן הם מגורסאים.

| קובץ | מה זה |
|---|---|
| `readings/batch_*.json` | הקריאה הראשונה — לכל תכנית: יח"ד, נדרש/מוצע, מגורים, אורחים, אופניים, אופנועים, נגישות, תפעולי, נוסח התקן והערות |
| `byuse_out_0..5.json` | המעבר השני — פילוח היתרה הלא-מגורים לשימושי קרקע, מנה לכל קורא |
| `byuse_manual_out.json` | הפילוח לתכניות שנקראו ידנית (כמה גיליונות לתכנית) |
| `byuse_base_fixes.json` | תיקונים לנתוני הבסיס **והנימוק לכל אחד**. הקריאה המקורית נשארת ב-`readings/` — התיקון לא מוחק אותה |
| `doc_index*.json` | רשימת **כל** שמות המסמכים של כל תכנית במבא"ת, לא רק הנבחר |
| `read_queue.json` | תור הקריאה ההיסטורי |

## למה `doc_index` חשוב

כי הוא מה שמאפשר להוכיח בדיעבד ש"אין נספח" הוא ממצא ולא פספוס. כשהתברר שביטוי
הזיהוי לא תפס את צורת הרבים `חניות`, סריקה חוזרת של 510 רשימות המסמכים צמצמה את
החשד ל-12 מועמדים ומהם לפספוס אמיתי אחד. בלי הרשימה המלאה זה לא היה ניתן לבדיקה.
**כל סורק-מסמכים חדש צריך לשמור את הרשימה המלאה.**

## מה *לא* כאן

`pdf/`, `crops/`, `zips/` — כ-2.5 ג"ב של הורדות גולמיות. נשארים מקומית תחת
`C:\ORANIM\traffic_appendices` ונוצרים מחדש מ-Mavat עם `scripts/fetch_traffic_appendices.py`.
הסקריפטים מחפשים אותם ב-`TRAFFIC_WORK_DIR` (ברירת מחדל: הנתיב לעיל).

## הרצה

```
py scripts/merge_byuse.py        # ראיות הפילוח → parking_evidence/byuse.json
py scripts/build_parking_json.py # readings + byuse + תיקונים → data/parking.json
```

⚠️ כששינוי ב-`byuse_base_fixes.json` מזיז `req_private`/`req_residential`, צריך
**שני מעברים** של merge→build: יעד הסגירה נקרא מ-`parking.json`, והמעבר הראשון
עדיין רואה את הסכומים הישנים.
